# OZ | Origins Zaruba — модификация для Fabric 1.20.1

Первая гибридная версия переноса OZ из datapack в серверный Fabric-мод. Цель v0.1.0 — убрать самые дорогие для сервера костыли, не ломая уже работающие режимы, команды, лобби и Origins-flow.

## Что уже перенесено в Java

### 1. Быстрый поиск зоны без генерации чанков
Старый OZ проверял удалённые кандидаты через marker-сущности + `forceload`, затем делал десятки biome-check команд. Это заставляло сервер грузить или генерировать чанки только ради проверки кандидата.

Теперь `ZoneSearchManager`:
- берёт `BiomeSource` и `MultiNoiseSampler` текущего генератора мира;
- оценивает 5×5 точек кандидата напрямую по данным генератора;
- не ставит `forceload` на кандидаты;
- не создаёт marker для каждого кандидата;
- проверяет до 24 кандидатов вместо старых 5;
- сохраняет старый порядок секторов 1..256 (проверено против v10.11);
- если идеального варианта нет, выбирает лучший из просмотренных, а не просто завершает поиск ошибкой;
- историю секторов хранит отдельно и пишет на диск пачками, а не на каждом тике.

Фильтры сохранены: любая / вода / горы / смешанная.

### 2. Бордер без сотен generated-функций
В v10.11 было 392 generated-функции только для вычисления динамического шага worldborder.

В моде время до целевого размера считается обычной Java-математикой и вызывается через `oz border refresh`.

Итог по встроенным функциям:
- было: 538 `.mcfunction`;
- стало: 132 `.mcfunction`;
- generated border tree: 392 → 0.

### 3. Более короткий матч
Дефолт v0.1.0:
- 00:00 — начало;
- 25:00 — может начинаться давление центра из существующей логики OZ;
- 30:00 — основная финальная стадия / начало штатного сужения;
- ~50:00 — штатное сужение должно закончиться;
- 50:00 — OVERTIME, бордер начинает уходить к 48×48;
- 55:00 — оставшиеся участники регулярно получают Glowing;
- 60:00 — SUDDEN DEATH, бордер становится максимум 24×24.

Death Pressure из OZ сохранён, поэтому смерти могут приблизить финал и ускорить сужение ещё сильнее.

### 4. Вертикальное давление против затягивания
Полёт не отключается и копание не запрещается. Вместо этого после 35-й минуты появляется мягкий вертикальный коридор вокруг локальной поверхности.

По умолчанию:
- верхний запас постепенно уменьшается примерно с +48 до +24 блоков над поверхностью;
- нижний — с -48 до -28;
- через 5 секунд нарушения появляется предупреждение и подсветка;
- через 10 секунд начинается урон;
- игрока, который слишком долго висит высоко, дополнительно тянет вниз.

Таким образом летающий Origin всё ещё может использовать полёт в бою, но не может бесконечно висеть за пределами нормальной досягаемости. Аналогично игрок не может бесконечно сидеть глубоко под землёй.

Давление сейчас работает только в Overworld. Это намеренно: высотная модель Nether требует отдельной логики из-за крыши мира.

### 5. Визуальные изменения v0.1
Полного клиентского GUI пока нет — v0.1 остаётся server-side модом. Но уже добавлены:
- actionbar-прогресс поиска зоны;
- сообщения с оценкой воды/гор каждого кандидата;
- отдельные title/subtitle для OVERTIME и SUDDEN DEATH;
- смена текста bossbar в жёстких фазах;
- старое книжное меню OZ сохранено, чтобы не ломать привычный workflow.

## Конфиг
После первого запуска создаётся:

`config/oz/oz.json`

Основные поля:
- `zoneSearch.maxCandidates` — сколько зон максимум оценивать;
- `zoneSearch.samplesPerAxis` — плотность биомных проб;
- `match.finalStartMinutes` — основная финальная стадия;
- `match.shrinkMinutes` — базовая длительность штатного сужения;
- `match.overtimeStartMinutes` — старт овертайма;
- `match.revealAllMinutes` — массовый Glowing;
- `match.suddenDeathMinutes` — жёсткое схлопывание;
- `pressure.*` — вертикальное давление.

При сбросе настроек лобби Java-конфиг заново накладывает свои дефолтные временные значения на scoreboard OZ.

Команды админа:
- `/oz zone search`
- `/oz zone search any|water|mountain|mixed`
- `/oz zone cancel`
- `/oz zone status`
- `/oz zone origin ensure`
- `/oz zone origin reset`
- `/oz border refresh`
- `/oz config show`
- `/oz config apply`
- `/oz info`

## Установка после сборки
Нужно:
- Minecraft 1.20.1;
- Fabric Loader;
- Fabric API;
- Origins и его обычные зависимости;
- Java 17.

**Старый ZIP OZ не нужно одновременно оставлять в `world/datapacks`.** Его проверенные data-ресурсы уже встроены внутрь мода. Две копии одних и тех же namespace/function ID только усложнят загрузку и отладку.

## Как собрать исходник
Проект настроен на:
- Yarn `1.20.1+build.10`;
- Fabric Loader `0.16.14`;
- Fabric API `0.92.2+1.20.1`;
- Fabric Loom `1.6.11`;
- Java 17.

Если Gradle установлен локально:

```bash
gradle build
```

Готовый remapped JAR появится примерно здесь:

`build/libs/oz-origins-zaruba-0.1.0.jar`

В этой рабочей среде Gradle и Maven/Fabric-зависимости недоступны по сети, поэтому здесь выполнена проверка структуры/JSON/function-ссылок и Java-синтаксиса, но финальный Fabric JAR **не был честно скомпилирован и запущен на Minecraft 1.20.1**. Не стоит выдавать сырой обычный `jar` за рабочий мод: Loom должен remap-нуть Yarn-имена в intermediary.

## Что пока сознательно не перенесено
v0.1 — не «переписать всё ради переписывания». Пока внутри JAR остаются хорошие части datapack: лобби, режимы, команды-книги, награды, стартовый flow и часть таймеров/Death Pressure.

Также пока не сделаны:
- полноценное клиентское меню настроек;
- Java pregenerator выбранной арены;
- новый генератор из заранее подготовленных мини-зон;
- требования к количеству структур при выборе зоны;
- полноценная анти-stall логика для Nether.

## Следующий логичный этап: структуры и мини-зоны
Для структуры я бы не привязывался к API каждого отдельного dungeon-мода. Правильнее работать через Minecraft registry:

1. В конфиге задаются ID или теги структур, например ванильные и структуры двух установленных модов.
2. Для кандидата сначала делается дешёвая оценка placement/registry без генерации всей арены.
3. Только для нескольких лучших кандидатов выполняется контролируемая генерация нужного участка.
4. После генерации идёт точная проверка реальных `StructureStart` в границе.
5. Условие вроде `minTotalStructures = 3` определяет, допускается ли зона.

Для «мира из мини-зон» лучше сделать отдельный arena preset, а не пытаться перекроить обычный Overworld во время матча: сетка подготовленных ячеек/шаблонов, выбор набора по seed, затем размещение заданных POI/структур. Это даст предсказуемую PvP-геометрию и позволит делать разные наборы арен без гигантского поиска по миру.


## v0.1.1 pacing / OZ Storm

Default pacing now targets a compact match:

- 0:00-18:00: development / respawn phase
- 18:00-42:00: hunt + border shrink
- 42:00: hard final begins
- 45:00: remaining players are periodically revealed
- 48:00: sudden-death 24x24 collapse

The old vertical arena pressure is presented as **OZ Storm**. From 18:00 it progressively closes the safe vertical band around the local terrain surface. Players outside the band are warned, then pushed back toward the surface from either direction, and finally take scaling damage. Flight and digging remain usable for combat and movement; indefinite sky/depth stalling is the behavior being removed.
